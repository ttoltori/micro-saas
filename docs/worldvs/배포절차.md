# World VS — Supabase & Vercel 배포 절차

> `AGENTS.md`의 원칙("각 서비스는 독립적으로 빌드하고 배포할 수 있어야 한다")에 따라, `worldvs-web`(프론트엔드)과 `worldvs-api`(백엔드)를 **별도의 Vercel 프로젝트 2개**로 배포하는 것을 기준으로 설명한다. 데이터베이스는 Supabase PostgreSQL을 사용한다.

```
[worldvs-web 프로젝트]  →  Vercel (Next.js)
[worldvs-api 프로젝트]  →  Vercel (Node.js Serverless Function, Hono)
                                  ↓
                          Supabase PostgreSQL
```

---

## 1. Supabase 프로젝트 생성

1. [supabase.com](https://supabase.com) → **New Project** 생성 (Region은 Vercel 배포 리전과 가깝게 선택, 예: Northeast Asia)
2. 프로젝트 생성 완료 후 **Project Settings → Database → Connection string** 에서 다음 두 가지를 확보한다.
   - **Connection Pooling (Transaction mode, 6543 포트)**: 서버리스 환경(Vercel Functions)에 권장. 커넥션 수 제한 문제를 방지한다.
   - **Direct connection (5432 포트)**: 마이그레이션/시드 스크립트 실행 시 사용.
3. **Project Settings → API** 에서 `anon` key, `Project URL`을 확보한다 (현재 MVP는 REST API를 직접 구현했으므로 필수는 아니지만, 추후 Supabase 클라이언트 SDK 사용 시 필요).

### 1-1. 마이그레이션 및 시드 데이터 적용

로컬 PC에서 Supabase의 **Direct connection** 문자열을 사용해 1회 실행한다.

```env
# apps/worldvs-api/.env (임시로 Supabase Direct connection 지정)
DATABASE_URL=postgresql://postgres:[PASSWORD]@db.[PROJECT-REF].supabase.co:5432/postgres
```

```bash
pnpm db:migrate
pnpm db:seed
```

> 완료 후 `worldvs` 스키마에 `countries`, `indicators`, `quiz_questions`, `leaderboard` 등의 테이블이 생성된다 (`database/migrations/worldvs/001_init.sql` 기준).

### 1-2. RLS(Row Level Security) 정책 확인

백엔드 API가 서비스 롤 커넥션(Direct/Pooler 문자열 + DB 비밀번호)으로 직접 PostgreSQL에 접속하므로, MVP 단계에서는 RLS를 비활성화하거나 아래처럼 전체 read/insert를 허용해도 된다. 단, Supabase Studio에서 직접 노출되는 REST/Realtime을 쓰지 않는다면 필수는 아니다.

```sql
alter table worldvs.leaderboard enable row level security;
create policy "public read" on worldvs.leaderboard for select using (true);
create policy "public insert" on worldvs.leaderboard for insert with check (true);
```

## 2. `worldvs-api` — Vercel 프로젝트 배포 (백엔드)

### 2-1. 서버리스 진입점

Hono 앱은 `@hono/node-server/serve`로 상시 구동되는 서버 방식이라 서버리스 환경과 맞지 않는다. 이를 위해 Vercel Node.js 함수 규격에 맞춘 진입점이 `apps/worldvs-api/api/index.ts`에 준비되어 있다.

```ts
// apps/worldvs-api/api/index.ts
import type { IncomingMessage, ServerResponse } from "node:http";
import { getRequestListener } from "@hono/node-server";
import { createApp } from "../src/app.js";

const app = createApp();
const listener = getRequestListener(app.fetch);

export default function handler(req: IncomingMessage, res: ServerResponse) {
  return listener(req, res);
}
```

`apps/worldvs-api/vercel.json`은 모든 경로를 이 함수로 라우팅한다.

```json
{
  "rewrites": [
    { "source": "/(.*)", "destination": "/api" }
  ]
}
```

### 2-2. Vercel 프로젝트 생성

1. Vercel 대시보드 → **Add New → Project** → GitHub 저장소 Import
2. **Root Directory**: `apps/worldvs-api` 로 지정 (모노레포이므로 반드시 설정)
3. **Framework Preset**: `Other` 선택
4. **Build Command / Output Directory**: 비워둠 (서버리스 함수만 사용하므로 별도 빌드 불필요. `pnpm install`만 수행되면 충분)
5. **Install Command**: 기본값 사용 (`pnpm install`, 루트의 workspace 의존성을 함께 설치하기 위해 Vercel의 "Include files outside root directory" 옵션이 자동 적용됨. pnpm 모노레포는 Vercel이 자동 인식한다)

### 2-3. 환경 변수 등록

Vercel 프로젝트 → **Settings → Environment Variables** 에 등록한다.

| Key | Value | 비고 |
|---|---|---|
| `DATABASE_URL` | Supabase **Connection Pooling** 문자열 (6543 포트) | 서버리스 다중 인스턴스 대비 |
| `APP_BASE_URL` | `https://<worldvs-api-project>.vercel.app` | 배포 후 실제 URL로 갱신 |
| `LOG_LEVEL` | `info` | 선택 |

### 2-4. 배포

```bash
git push origin main
```

Vercel이 GitHub 연동을 통해 자동 배포한다. 배포 완료 후 확인:

```bash
curl https://<worldvs-api-project>.vercel.app/health
# {"status":"ok"}
```

## 3. `worldvs-web` — Vercel 프로젝트 배포 (프론트엔드)

### 3-1. Vercel 프로젝트 생성

1. Vercel 대시보드 → **Add New → Project** → 동일 GitHub 저장소 Import (별도 프로젝트로 추가)
2. **Root Directory**: `apps/worldvs-web`
3. **Framework Preset**: `Next.js` (자동 인식됨)
4. Build/Output/Install Command는 기본값 유지

### 3-2. 환경 변수 등록

| Key | Value |
|---|---|
| `NEXT_PUBLIC_API_URL` | `https://<worldvs-api-project>.vercel.app` (2단계에서 배포한 API 주소) |

### 3-3. 배포

`main` 브랜치에 push하면 자동 배포된다. 배포 완료 후 브라우저에서 확인:

```
https://<worldvs-web-project>.vercel.app
```

## 4. 배포 후 점검 체크리스트

| 항목 | 확인 방법 |
|---|---|
| API 헬스체크 | `GET /health` → `{"status":"ok"}` |
| 국가 목록 | `GET /v1/countries` 응답 확인 |
| CORS | 프론트엔드에서 API 호출 시 콘솔에 CORS 에러 없는지 확인 (`app.ts`의 `cors()` 미들웨어가 전체 허용 중이므로 기본적으로 문제 없음) |
| 국가 비교 페이지 | `/compare/KR/JP` 등 실제 데이터 렌더링 확인 |
| 퀴즈 → 리더보드 플로우 | 퀴즈 완료 후 점수 등록이 Supabase `leaderboard` 테이블에 반영되는지 확인 |
| DB 커넥션 한도 | Supabase 대시보드 → **Database → Connection Pooling** 에서 활성 커넥션 수 모니터링 (서버리스 특성상 급증 가능) |

---

## 5. 커스텀 도메인 연결 (선택)

1. `worldvs-web` 프로젝트 → **Settings → Domains** → 도메인 추가 (예: `worldvs.com`)
2. `worldvs-api` 프로젝트 → 서브도메인 연결 (예: `api.worldvs.com`)
3. 프론트엔드 환경 변수 `NEXT_PUBLIC_API_URL`을 `https://api.worldvs.com`으로 갱신 후 재배포

---

## 6. 참고 — 루트 `vercel.json`에 대한 안내

저장소 루트의 `vercel.json`은 두 앱을 하나의 Vercel 프로젝트로 묶어 배포하던 legacy(`builds`/`routes`) 설정이며, 위에서 설명한 **2개 프로젝트 분리 배포 방식**에서는 사용하지 않는다. 각 앱의 Root Directory를 지정해 별도 프로젝트로 배포하면 루트 `vercel.json`은 무시된다.
