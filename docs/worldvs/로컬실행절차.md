# World VS — 로컬 실행 절차

> `AGENTS.md`의 모노레포 구조를 기준으로, `worldvs-web`(Next.js)과 `worldvs-api`(Hono) 두 서비스를 로컬 PC에서 실행하는 절차를 설명한다.

---

## 1. 사전 준비

| 항목 | 요구 버전 | 확인 명령 |
|---|---|---|
| Node.js | 20 이상 (22 권장) | `node --version` |
| pnpm | 최신 | `pnpm --version` (없으면 `npm install -g pnpm`) |
| Supabase 프로젝트 | - | [supabase.com](https://supabase.com) 에서 생성 |

Windows에서 Node.js가 없다면 `nvm4w`(nvm for Windows)로 설치할 수 있다.

```bash
nvm install 22.14.0
nvm use 22.14.0
npm install -g pnpm
```

---

## 2. 저장소 의존성 설치

프로젝트 루트(`root/`)에서 실행한다.

```bash
pnpm install
```

pnpm이 빌드 스크립트를 실행할지 묻는 경우(`esbuild`, `sharp` 등) 아래 명령으로 승인한다.

```bash
pnpm approve-builds
```

> `pnpm-workspace.yaml`의 `onlyBuiltDependencies`에 이미 `esbuild`, `sharp`가 등록되어 있어 최초 1회만 필요하다.

---

## 3. Supabase 프로젝트 준비

1. Supabase 대시보드 → **Project Settings → Database** 에서 Connection String(URI, `Session pooler` 또는 `Direct connection`)을 복사한다.
2. 로컬 개발에서는 **Direct connection** 문자열 사용을 권장한다 (마이그레이션 스크립트가 다수의 짧은 커넥션을 생성하기 때문).

```
postgresql://postgres:[YOUR-PASSWORD]@db.[PROJECT-REF].supabase.co:5432/postgres
```

---

## 4. 환경 변수 설정

### 4-1. `apps/worldvs-api/.env`

```env
DATABASE_URL=postgresql://postgres:[YOUR-PASSWORD]@db.[PROJECT-REF].supabase.co:5432/postgres
PORT=3001
APP_BASE_URL=http://localhost:3001
LOG_LEVEL=info
```

### 4-2. `apps/worldvs-web/.env.local`

```env
NEXT_PUBLIC_API_URL=http://localhost:3001
```

> 두 파일 모두 저장소에 커밋하지 않는다. `.gitignore`에 `.env`, `.env.local`이 포함되어 있는지 확인한다.

---

## 5. 데이터베이스 마이그레이션 및 시드 데이터 삽입

루트에서 실행한다 (내부적으로 `apps/worldvs-api`의 `DATABASE_URL`을 사용한다).

```bash
pnpm db:migrate   # database/migrations/worldvs/*.sql 순서대로 실행
pnpm db:seed      # database/seeds/worldvs/*.sql 순서대로 실행 (국가, 지표, 값, 퀴즈 문항)
```

정상 실행 시 콘솔에 각 SQL 파일명과 `✓ Done`이 출력된다.

---

## 6. 개발 서버 실행

### 6-1. 두 서비스 동시 실행

```bash
pnpm dev
```

### 6-2. 개별 실행 (디버깅 시 권장)

```bash
# 터미널 1 — 백엔드 (Hono, http://localhost:3001)
pnpm dev:api

# 터미널 2 — 프론트엔드 (Next.js, http://localhost:3000)
pnpm dev:web
```

---

## 7. 동작 확인

| 확인 항목 | 방법 |
|---|---|
| API 헬스체크 | 브라우저 또는 `curl http://localhost:3001/health` → `{"status":"ok"}` |
| 국가 목록 API | `curl http://localhost:3001/v1/countries` |
| 프론트엔드 홈 | 브라우저에서 `http://localhost:3000` 접속 |
| 국가 비교 | `/compare` → 두 국가 선택 → 비교 결과 페이지 확인 |
| 퀴즈 플로우 | `/quiz` → 세션 시작 → 10문항 응답 → 결과 페이지 확인 |
| 리더보드 | 퀴즈 완료 후 `/leaderboard/register` → 등록 → `/leaderboard`에서 순위 확인 |

---

## 8. 빌드 검증 (배포 전 로컬 점검)

```bash
pnpm build
```

- `apps/worldvs-api`: `tsc`로 `dist/`에 컴파일된 JS 산출
- `apps/worldvs-web`: `next build`로 `.next/`에 프로덕션 빌드 산출, 8개 라우트가 모두 정적/동적으로 생성되는지 확인

---

## 9. 자주 발생하는 문제

| 증상 | 원인 | 해결 |
|---|---|---|
| `DATABASE_URL is not set` | `.env` 파일 누락 | `apps/worldvs-api/.env` 생성 확인 |
| `ERR_PNPM_IGNORED_BUILDS` | 빌드 스크립트 미승인 | `pnpm approve-builds` 실행 |
| `tsc ""` 관련 `TS6231` 에러 | pnpm이 빈 문자열 인자를 스크립트에 추가하는 Windows 환경 이슈 | 각 패키지의 `build`/`typecheck` 스크립트가 `tsx -e "..."` 래퍼를 사용하도록 구성되어 있어 정상 동작함. 직접 `tsc`를 호출할 경우에만 발생 |
| CORS 에러 | `NEXT_PUBLIC_API_URL` 미설정 또는 API 서버 미기동 | `.env.local` 확인 및 `pnpm dev:api` 기동 여부 확인 |
| 퀴즈 세션 조회 404 | 마이그레이션 미적용 (`quiz_session_questions` 테이블 없음) | `pnpm db:migrate` 재실행 |
