## 1. 앱 개요

**세계는 지금**은 앱을 열면 세계 주요 국가 사람들이 지금 무엇에 관심을 갖고 있는지 한눈에 보여주는 Android 앱이다.

국가별로 현재 시간, 현재 날씨, 실시간 트렌드 키워드, 관련 이미지, 자동 번역, AI 한 줄 설명을 카드 형태로 보여준다. MVP는 **5개 화면, 6개 국가 타일 UI**로 빠르게 출시하고, 반응에 따라 지도형·알림형·뉴스형으로 확장한다.

## 4. MVP 핵심 컨셉

초기 버전은 복잡한 기능을 넣지 않고 다음 가치에 집중한다.

1. 앱을 열자마자 세계 여러 나라의 "지금"이 보인다.
2. 모르는 외국어 트렌드어도 자동 번역되어 이해할 수 있다.
3. 키워드만 보는 것이 아니라 관련 이미지를 함께 보여줘서 시각적으로 재미있다.
4. 시간과 날씨가 함께 표시되어 "현지감"이 있다.
5. 타일을 누르면 왜 뜨는 키워드인지 AI가 짧게 설명해준다.

# 화면 1. 홈 — 세계 트렌드 6타일

## 목적

앱의 메인 화면. 사용자가 앱을 열자마자 6개 국가의 현재 트렌드를 카드 형태로 볼 수 있다.

## 화면 구성

기본 6개 타일:

* 🇰🇷 한국
* 🇯🇵 일본
* 🇺🇸 미국
* 🇹🇭 태국
* 🇫🇷 프랑스
* 🇧🇷 브라질

각 타일 표시 정보:

* 국가명 + 국기
* 현재 현지 시간 (클라이언트 timezone 계산)
* 현재 온도 + 날씨 아이콘
* 대표 트렌드 키워드 3개 (원문 + 번역)
* 대표 이미지 1장
* 데이터 업데이트 시각

## 예시

```
🇯🇵 일본
18:42 · 24℃ · 흐림

오늘의 트렌드
1. 大谷翔平   → 오타니 쇼헤이
2. 梅雨明け   → 장마 종료
3. コンビニ新作 → 편의점 신제품
```

## 사용자 액션

* 타일 탭 → 국가 상세 화면 이동
* 새로고침 → 최신 데이터 수동 갱신
* 언어 토글 → 한국어 / 일본어 전환

> **1차 기획안에서 제거**: "타일 길게 누르기 즐겨찾기"는 내 월드 화면에서 처리한다.

## 기술 요구사항

* Supabase REST API `/rest/v1/` 호출 (Retrofit2)
* 국가별 현재 시간: Android `ZoneId` 로컬 계산 (서버 불필요)
* 날씨: OpenWeatherMap Free Tier (서버 배치에서 1시간마다 수집 후 Supabase에 캐시)
* 트렌드: 서버 배치가 미리 수집·번역·저장한 캐시 데이터 사용
* 이미지: URL만 저장, Glide 라이브러리로 로딩

## API 예시

```http
GET https://<project>.supabase.co/rest/v1/home_view?lang=ko
```

# 화면 2. 국가 상세 — [국가]는 지금

## 목적

선택한 국가의 트렌드를 더 자세히 보여준다.

## 화면 구성

상단:

* 국가명 + 국기
* 현재 시간 + 날씨
* 오늘의 분위기 한 줄 (AI 생성, 배치 시점에 미리 생성)

본문 (트렌드 키워드 최대 10개, RecyclerView):

* 원문 키워드 + 번역
* 상승 상태 또는 검색량 텍스트
* 관련 이미지 썸네일
* AI 한 줄 설명
* 관련 뉴스/검색 링크

## 사용자 액션

* 키워드 탭 → 키워드 상세 화면 이동
* 공유 → 이미지 카드 형태로 SNS 공유
* 번역 보기/원문 보기 전환 (토글 버튼)

## 기술 요구사항

* Supabase `trend_items` 테이블 조회
* AI 요약은 배치 단계에서 미리 생성 (매 요청마다 OpenAI 호출 ❌)
* 관련 이미지 URL 1개 저장 (배치에서 수집)

## API 예시

```http
GET https://<project>.supabase.co/rest/v1/trend_items?snapshot_id=eq.{id}&order=rank_no
```

```
실행 환경  : GitHub Actions (Free: 2,000분/월)

스케줄     : 트렌드 3시간마다 / 날씨 1시간마다
Supabase 저장: supabase-py 클라이언트 사용
```

### 6.4 외부 API (무료 위주)

| 역할 | 서비스 | 비용 |

## 7. 데이터 소스 전략

### 7.1 트렌드 데이터

**1순위: pytrends (비공식 Google Trends 라이브러리)**

```python
from pytrends.request import TrendReq
pytrends = TrendReq(hl='ja-JP', tz=540)
df = pytrends.trending_searches(pn='japan')
```

* 무료이지만 Google 정책 변경에 취약
* 배치에서만 사용하고 결과를 DB에 저장 → 앱은 DB만 조회
* 수집 실패 시 이전 캐시 데이터 유지 (필수)

**2순위: Google Trends RSS / Trending Now 페이지**

```
https://trends.google.com/trending/rss?geo=JP
```

* 국가 코드(`geo`)만 변경하면 각국 트렌드 RSS 수신 가능
* XML 파싱으로 제목·링크·뉴스 썸네일 추출 가능
* pytrends 실패 시 자동 대체

**지원 국가별 geo 코드**

| 국가 | geo 코드 |
|---|---|
| 한국 | KR |
| 일본 | JP |
| 미국 | US |
| 태국 | TH |
| 프랑스 | FR |
| 브라질 | BR |

> **제외**: pytrends를 앱 클라이언트에서 직접 호출하는 방식은 금지. 반드시 배치 → DB → API 구조 유지.

### 7.2 이미지 데이터

**전략: 이미지 URL만 저장하며 파일 자체는 저장하지 않는다.**

우선순위:

1. Google Trends RSS 뉴스 썸네일 (`<ht:news_item><ht:picture>` 태그)
   — 트렌드 RSS에 이미 포함되어 있어 별도 API 호출 불필요
2. Google Custom Search JSON API (무료: 100 queries/day)
   — 신규 키워드에만 호출, DB 캐시 재사용으로 일일 한도 내 유지
3. Fallback: 국가별 기본 대표 이미지 (앱에 포함된 drawable 리소스)

> **주의**: 이미지 저작권은 URL 링크 표시 방식(원본 출처 링크 제공)으로 대응. 이미지 파일 서버 저장 금지.

### 7.3 날씨 데이터

* OpenWeatherMap Free Tier (1,000 calls/day)
* 국가별 대표 도시 1개만 호출 (6개 도시 = 6 calls/시간)
* 배치에서 1시간마다 수집 → `weather_cache` 테이블에 저장

| 국가 | 대표 도시 |
|---|---|
| 한국 | Seoul |
| 일본 | Tokyo |
| 미국 | New York |
| 태국 | Bangkok |
| 프랑스 | Paris |
| 브라질 | São Paulo |

### 7.4 번역

* **DeepL Free API**: 키워드 원문 → 한국어/일본어 번역 (500k 글자/월)
* 동일 키워드가 이미 DB에 있으면 재번역하지 않고 캐시 사용
* DeepL 실패 시 fallback: OpenAI 번역 프롬프트

### 7.5 AI 요약

* OpenAI GPT-3.5-turbo
* 신규 키워드에만 생성 (DB에 없는 경우만)
* 언어별 캐싱: 한국어 요약, 일본어 요약 각각 저장
* 민감 키워드 분류도 OpenAI로 처리

## 8. 시스템 아키텍처

```
[Android 앱 (Java)]
        ↓ Retrofit2 REST
[Supabase REST API / Edge Functions]
        ↓
[Supabase PostgreSQL]
        ↑
[GitHub Actions Cron (Python)]
        ↓ 수집
[pytrends / Google Trends RSS / OpenWeatherMap / DeepL / OpenAI]
```

### 흐름 요약

1. GitHub Actions가 3시간마다 트렌드 배치를 실행한다.
2. 배치는 각국 트렌드를 수집하고 번역·AI 요약을 생성하여 Supabase DB에 저장한다.
3. 앱은 Supabase REST API를 통해 DB에서 캐시 데이터를 조회한다.
4. 앱은 절대로 트렌드 소스(pytrends, Google Trends 등)에 직접 접근하지 않는다.

## 9. 데이터베이스 설계

### 9.1 countries

```sql
CREATE TABLE countries (
    country_code VARCHAR(2) PRIMARY KEY,
    name_ko      VARCHAR(100),
    name_ja      VARCHAR(100),
    name_en      VARCHAR(100),
    flag_emoji   VARCHAR(10),
    timezone     VARCHAR(100),
    default_city VARCHAR(100),
    latitude     NUMERIC(10, 6),
    longitude    NUMERIC(10, 6),
    sort_order   INT,
    is_active    BOOLEAN DEFAULT TRUE
);
```

### 9.2 trend_snapshots

국가별 특정 시점의 트렌드 묶음.

```sql
CREATE TABLE trend_snapshots (
    id            BIGSERIAL PRIMARY KEY,
    country_code  VARCHAR(2) REFERENCES countries(country_code),
    source        VARCHAR(50),        -- 'pytrends' | 'rss'
    snapshot_time TIMESTAMP WITH TIME ZONE,
    summary_ko    TEXT,               -- AI 생성 오늘의 분위기 한 줄
    summary_ja    TEXT,
    created_at    TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);
```

### 9.3 trend_items

개별 트렌드 키워드.

```sql
CREATE TABLE trend_items (
    id                BIGSERIAL PRIMARY KEY,
    snapshot_id       BIGINT REFERENCES trend_snapshots(id),
    rank_no           INT,
    keyword_original  VARCHAR(300),
    keyword_ko        VARCHAR(300),
    keyword_ja        VARCHAR(300),
    search_volume_text VARCHAR(100),
    trend_status      VARCHAR(50),   -- 'rising' | 'hot' | 'new'
    ai_summary_ko     TEXT,
    ai_summary_ja     TEXT,
    category          VARCHAR(50),
    image_url         TEXT,
    source_url        TEXT,
    is_sensitive      BOOLEAN DEFAULT FALSE,
    created_at        TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);
```

### 9.4 weather_cache

```sql
CREATE TABLE weather_cache (
    id               BIGSERIAL PRIMARY KEY,

    city_name        VARCHAR(100),
```

## 10. Supabase API 목록

Android 앱은 Supabase Auto REST API(PostgREST)를 Retrofit2로 직접 호출한다.

### 10.1 홈 데이터 (최신 스냅샷 6개국)

```http
GET /rest/v1/trend_snapshots
    ?select=*,countries(*),trend_items(*)
    &order=snapshot_time.desc
    &limit=6
Authorization: Bearer <SUPABASE_ANON_KEY>
```

### 10.2 국가별 트렌드 상세

```http
GET /rest/v1/trend_items
    ?snapshot_id=eq.{snapshotId}
    &is_sensitive=eq.false
    &order=rank_no
    &limit=10
```

### 10.3 키워드 상세

```http
GET /rest/v1/trend_items?id=eq.{itemId}
```

### 10.4 국가 목록

```http
GET /rest/v1/countries?is_active=eq.true&order=sort_order
```

### 10.5 날씨 (최신 1건)

```http
GET /rest/v1/weather_cache
    ?country_code=eq.{code}
    &order=observed_at.desc
    &limit=1
```

> **보안**: Android 앱에는 Supabase `anon key`만 사용한다. Row Level Security(RLS)를 활성화하여 읽기만 허용하고 쓰기는 차단한다.

## 11. 배치 작업 설계 (GitHub Actions + Python)

### 11.1 트렌드 수집 배치

**파일**: `.github/workflows/collect_trends.yml`

```yaml
on:
  schedule:
    - cron: '0 */3 * * *'   # 3시간마다
  workflow_dispatch:         # 수동 실행 가능
```

**처리 순서:**

```
1. 활성 국가 목록 Supabase에서 조회
2. 각 국가 Google Trends RSS 수집 (pytrends fallback)
3. 직전 스냅샷과 비교하여 신규 키워드만 추출
4. 신규 키워드 DeepL Free API로 번역 (캐시 없는 것만)
5. 신규 키워드 OpenAI GPT-3.5-turbo로 AI 요약 생성
6. OpenAI로 민감 키워드 분류
7. 뉴스 RSS 썸네일 URL 추출
8. Supabase trend_snapshots / trend_items 저장
9. 오늘의 분위기 한 줄 생성 (스냅샷당 1회)
10. 실패 로그 기록 (GitHub Actions 아티팩트)
```

### 11.2 날씨 수집 배치

**파일**: `.github/workflows/collect_weather.yml`

```yaml
on:
  schedule:
    - cron: '0 * * * *'   # 1시간마다
```

**처리 순서:**

```
1. 국가별 대표 도시 조회
2. OpenWeatherMap API 호출 (6 calls)
3. 온도, 날씨 텍스트, 아이콘 Supabase weather_cache에 저장
```

### 11.3 수집 실패 정책

* 수집 실패 시 마지막 성공 데이터를 유지한다 (앱에서 "N시간 전 데이터" 표시).
* 연속 3회 실패 시 GitHub Actions 이메일 알림 발송.
* 배치 실패가 앱 표시에 영향을 주지 않도록 캐시 DB가 항상 최후 보루 역할을 한다.

## 17. 출시 전 주요 리스크

### 17.1 pytrends 불안정성 (높음)

Google이 비공식 접근을 차단하면 pytrends가 동작하지 않는다.

**대응**: Google Trends RSS를 항상 1차 소스로 사용하고, pytrends는 상세 데이터 보조용으로 격하한다. RSS 실패 시에도 이전 캐시 데이터를 표시한다.

### 17.2 이미지 저작권 (중간)

Google Custom Search 및 뉴스 썸네일은 저작권이 제3자에 있다.

**대응**: 이미지 파일을 서버에 저장하지 않고 URL 링크 방식으로만 표시한다. 출처 링크를 함께 제공한다. 향후 상업화 전에 이미지 API 약관을 재검토한다.

### 17.3 민감 키워드 노출 (중간)

범죄, 자살, 정치, 성인 관련 키워드가 트렌드에 포함될 수 있다.

**대응**: AI 민감 분류 + `is_sensitive=true` 키워드 흐림 처리. 초기에는 민감 키워드는 숨김 처리로 안전하게 운영한다.

### 17.4 번역 오류 (낮음)

신조어, 밈, 고유명사는 DeepL/OpenAI도 틀릴 수 있다.

**대응**: 앱 내에 "AI 번역은 부정확할 수 있습니다" 안내 문구를 표시한다.

### 17.5 Supabase Free Tier 한계 (낮음, 초기 MVP는 충분)

무료 티어 DB 500MB, Edge Functions 500k/월.

**대응**: 오래된 스냅샷 자동 삭제 배치 추가 (30일 이상 데이터 정리). 사용자 증가 시 Pro Tier ($25/월) 업그레이드 검토.

## 결론

첫 버전은 **"세계 각국의 지금 뜨는 검색어를 예쁜 카드로 보여주는 Android 앱"** 으로 단순하게 출시한다.

기술 스택은 Android Java + Supabase 서버리스 + GitHub Actions 배치로 확정하여 운영비를 최소화한다 (월 $1~2 수준). 트렌드 데이터는 Google Trends RSS를 기본으로 pytrends를 보조로 사용하며, 배치 실패 시에도 캐시 데이터로 앱이 정상 동작하도록 한다.

핵심은 데이터의 완벽함이 아니라, 사용자가 앱을 열었을 때 **"오, 일본에서는 이런 게 뜨고 있네?"** 라고 느끼게 만드는 것이다.
